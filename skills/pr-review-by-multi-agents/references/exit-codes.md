# 結束碼

`scripts/run-review.sh` 回傳非零結束碼時對照本檔，判斷這一次動到了什麼、要不要補救、怎麼補救。

`launch` 自己有三道檢查——環境閘門（`4`，五個子命令都掛同一道）、平台清單核對（`2`）、PATH 再驗（`3`）——其餘前置檢查落在 `prepare`。`run` 是 `prepare`、建 pane、`launch` 三段依序跑在同一個行程裡，兩半的結束碼語意原樣適用，建 pane 那一段自己失敗時是 `1`。

| 結束碼 | 原因 | 有沒有留下副作用 | 怎麼補救 |
| --- | --- | --- | --- |
| `0` | 成功：`prepare` 是座標已備妥、還沒有 reviewer 起來，`launch` 是已派出 | 正常流程 | 往下走 |
| `1` | 兩種性質相反的失敗共用這一碼：前置條件不成立（gh、jq、PR 存在性、git repo、`origin`、審查契約檔、base ref、worktree 建立或唯讀化、材料、prompt 尺寸任一不過），或 `launch` 派送途中失敗 | 「什麼都沒動到」只到找不到契約檔為止；再往後 repo 已被動過（遠端追蹤 ref 已更新、同形狀陳舊分支已強制刪除、pull ref 已 fetch 且本次分支已建立），強制刪除排在 pull ref 之前 | 靠標準錯誤有沒有指出已派出的 reviewer 分辨兩種性質，再照表下三條處置。例外是 PR 連結解析不出（`--pr` 打錯，或沒給連結而當前分支沒有對應的 PR），那是當場改旗標值或補上連結就能解的 |
| `2` | 用法錯誤：未知旗標、旗標缺值、`prepare` 一個平台旗標都沒給、旗標值含換行、`launch` 缺 `--base-dir` 或給了相對路徑、`--agent` 值不是 `<cli>=<pane_id>` 的形狀或重複、`--agent` 指名了這次 `prepare` 沒選中的平台、`--base-dir` 底下沒有 `.roster`；`wait` 與 `cleanup` 缺 `--base-dir`、`cleanup` 拿到的路徑不是絕對路徑或不存在，同樣落在這一碼 | 無 | 前面幾種當場改旗標；沒選中的平台與缺 `.roster` 那兩種改旗標沒用（沒選中的平台沒有 prompt 檔、工作目錄與隔離家目錄），要回頭重跑 |
| `3` | 選定的平台中有 CLI 不在 PATH 上，訊息會列出是哪幾個 | 不留副作用：這道排在所有 gh 往返與對 repo 的寫入之前 | 當場再問一次要跳過還是改挑；落在 `launch` 那次只做得到跳過（從 `--agent` 拿掉），改挑沒選中的平台會以 `2` 被拒、要重跑 `prepare` |
| `4` | 呼叫環境不成立：五個子命令各自在解析旗標與任何前置檢查之前確認 `HERDR_ENV` 恰為 `1` | 零副作用（本次執行目錄從未被建立是實測；「使用者的 repo 也從未被觸碰」是從控制流推得的推斷，測試沒有對應斷言） | 改旗標沒用，要在 herdr 環境裡重新發起 |

回報時先靠標準錯誤有沒有指出已派出的 reviewer 分兩種性質，處置相反：

- **沒有指出**：把訊息原文回報，**不重試、不改用其他途徑**——這類失敗全是環境前提不成立，繞道會在前提不成立下派出審查、產出沒有依據的 review。`2` 與 `3` 不屬於這一類，補救方向照上表那一列。
- **指出了**：原文轉達那份清單，說明這些 agent 無人監督、這次不會有監督行程去讀它們的輸出檔，結果只會停在各自的 `reviewers/<cli>/workdir/review.md` 裡，並把 pane 留著讓使用者決定要不要終止。

`1` 底下三條處置不在表格裡，逐條照做（其餘展開說明見 `rationale.md`）：

- **找不到審查契約檔**代表安裝不完整，照「兩條安裝路徑都不存在」處理，不要在沒有審查標準的情況下自行湊一份派出去。
- **這條路徑上留下的本次分支不要自己去刪**：訊息不印執行目錄，取不到分支名尾端那段行程編號；交給腳本的陳舊分支清除機制——worktree 還在時 git 擋著這個分支，要等針對**同一個 PR** 的下一次執行先移除 worktree，它才刪得掉。
- **執行目錄已建好時據實告訴使用者位置**，這些目錄不會被任何機制自動清掉：已經印過 `base_dir` 就交出去，還沒印到就請他到 `~/.tmp/<repo 名>-pr-<PR 編號>/` 底下看。派送途中失敗那一種另要轉達哪幾個 reviewer 成了無人監督的孤兒。
