# 多題

用來重述 agent 一次問了多題的討論點。每題自成一個區塊，前因後果緊跟著該題，對話者讀完一個區塊就能回答那一題。

## 一句話結論

講出題數，讓對話者知道後面有幾個區塊。全局前提照 SKILL.md。

## 題的順序與題號

- 題號沿用 agent 原本的題號，對話者照題號回覆 agent 時才不會對錯題。
- 題之間有依賴時，被依賴的題在前。
- 沒有依賴時，保留 agent 原本的順序。

## 逐題區塊

一題一個區塊，用標題分開。標題寫題號與該題要對話者回答什麼，標題本身就是該題重點。標題下依序寫：

1. **前因**：為什麼會出現這一題，補上對話者缺的前提。這題依賴前面某一題時，寫明依賴哪一題，以及那一題的答案不同時，這一題會怎麼變。
1. **後果**：有選項時，寫每個選項各會帶來什麼結果；沒有選項時，寫這個答案會影響什麼。
1. **圖**：每題 0 到 1 張，需要時才畫，取代 SKILL.md 的 1 到 3 張。形式照 SKILL.md 的形式選單。

## 範例

```markdown
agent 問了你 3 題，都跟新的簡訊驗證功能怎麼上線有關。

### 第 1 題：新的「手機號碼」欄位要不要設成必填？

**前因**：簡訊驗證要用手機號碼寄驗證碼。現有使用者註冊時還沒有這個欄位。

**後果**：
- 必填：每個帳號都收得到驗證簡訊，但舊使用者的資料不符合規則。
- 選填：舊資料不受影響，但沒填號碼的使用者收不到驗證簡訊。

### 第 2 題：舊使用者沒有手機號碼，要怎麼補？

**前因**：舊使用者的手機號碼欄位都是空的。依賴第 1 題：第 1 題選「必填」，這題才要回答；選「選填」，這題可以跳過。

**後果**：
- 上線前強制補填：上線當天，所有舊使用者都要先填號碼才能登入。
- 下次登入時補填：上線不受影響，但補填前，這些帳號仍收不到驗證簡訊。

### 第 3 題：什麼時候上線？

**前因**：行銷活動本週六開始，簡訊驗證要在活動前上線才用得到。依賴第 2 題：第 2 題選「上線前強制補填」，要先留時間通知舊使用者；選「下次登入時補填」，不必等通知。

**後果**：
- 本週五晚上：趕得上活動，但只剩兩天測試，也來不及先通知舊使用者。
- 下週二：測試和通知的時間都夠，但錯過活動。
```
