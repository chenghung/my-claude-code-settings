# clauth 智慧選 profile 規則說明

本文件說明 `clauto` 啟動器如何動態決定要用哪個 clauth profile（Claude 帳號）啟動 Claude Code。目的是讓日後調整規則時，不必從 jq 程式碼反推邏輯。

規則的唯一實作是 `_clauth_smart_pick` 函式（位於 `platforms/claude/clauth.zsh`；搬移前位於 `install-cli-tools.sh` 的 heredoc），對應測試在 `tests/test-cli-aliases.sh`。本文件與程式碼不一致時，以程式碼為準。

## 啟動流程總覽

`clauto` 與指向它的 alias `claude` 的流程如下：

1. 呼叫 `_clauth_smart_pick`，由它輸出選定的 profile 名稱。
1. 將 `==> [clauth] 選定 profile: <名稱>` 印到 stderr。
1. 執行 `clauth start <名稱>`，並在 `--` 分隔符號之後傳入 `--permission-mode auto` 與 `--settings`（指向本 repo 的 `platforms/claude/settings.json`），再接使用者追加的引數。

固定 profile 的 alias 不經過選擇器，永遠使用同一個帳號：

| Alias | Profile | 方案 |
| --- | --- | --- |
| `cl`、`cla`、`clc`、`clr`、`clw`、`clre` | `onramplab` | Team |
| `clp`、`clpc`、`clpr`、`clpw`、`clpre` | `personal` | Max |

## 輸入資料

- 資料來源是 `clauth status --json` 的輸出（stderr 被丟棄；指令失敗時視同無輸出）。
- 只考慮 `auth_status` 為 `ok` 的 profile。
- 每個 profile 的 `windows` 陣列中，以 `label` 為 `7d` 與 `5h` 的兩個用量視窗為準，各含 `utilization_pct`（已用百分比）與 `resets_at`（重置時間，ISO 8601）。
- 頂層的 `active_profile` 只在回退時使用。

## 變數定義

| 變數 | 定義 |
| --- | --- |
| `w` | 7d 剩餘配額：`100 - 7d 的 utilization_pct`。缺 7d 視窗視為已用滿，`w = 0` |
| `T` | 距離 7d 重置的小時數，下限 0.25 小時 |
| `r5` | 5h 剩餘配額：`100 - 5h 的 utilization_pct`。缺 5h 視窗視為尚未使用，`r5 = 100` |
| `t5` | 距離 5h 重置的小時數；缺視窗或已過期記為 0 |
| `c(t)` | 假設的每小時耗用率：台北時間（UTC+8）週一至週五 09:00 起、19:00 前（不含 19:00）為每小時 40%，其餘時間為每小時 25% |
| `E` | 從現在到 5h 重置的預期耗用量。以 15 分鐘為一個 slot，逐 slot 累加 `c(該 slot 起點) × 0.25`；最後不足 15 分鐘的 slot 依其佔比加權。沒有 5h 重置時間時 `E = 0` |
| `F` | `E = 0` 時為 1，否則為 `min(1, r5 / E)` |
| `U` | `max(w - 2, 0) / T` |
| `S` | 分數，`S = U × F` |

補充（皆依程式碼行為）：

- `t5` 只是概念上的量；程式中實際以「5h 重置時間減現在」計算 `E`，結果等價於 `t5 = 0` 時 `E = 0`。
- 7d 視窗存在但 `resets_at` 為 null 時，`T` 取下限 0.25，`U` 會被放大，須留意。
- 時間字串解析只接受以 `Z` 或 `+00:00` 結尾的格式（可帶小數秒）；其他時區偏移會使 jq 失敗，最終落到 `onramplab`。

## 設計直覺

- **U 偏好「每小時剩餘額度最多」的帳號**：`w` 是 7d 配額剩餘，除以距重置的時間 `T`，即每小時可用的額度。重置越近、剩越多的帳號 `U` 越高，對應「不用就浪費」（use-it-or-lose-it）。減 2 是保留安全邊際。
- **F 懲罰 5h 視窗可能提早耗盡的帳號**：若預期到 5h 重置前的耗用量 `E` 超過剩餘 `r5`，`F` 小於 1，分數按比例打折。

## 選擇步驟

1. 計算每個 `auth_status` 為 `ok` 的 profile 的 `w`、`r5`、`F`、`S`。
1. 剔除 `r5 <= 2` 或 `w <= 2` 的 profile，剩下的稱為候選池。
1. 在候選池中，若存在 `2 < w <= 5` 且 `F >= 0.5` 的 profile（7d 配額即將用完，但 5h 視窗仍撐得住），只在這些 profile 中取 `S` 最高者（「收尾」偏好）。
1. 否則在整個候選池中取 `S` 最高者。
1. 候選池為空時，回退到 `clauth status --json` 的 `active_profile`。
1. `active_profile` 也為空（或整個 jq 失敗、無輸出）時，回退到 `onramplab`。

## 測試用時間注入

環境變數 `CLAUTH_PICK_NOW`（epoch 秒）可覆寫「現在時間」，供測試以固定時間驗證。未設定時使用 `date +%s`。

## 計算範例

假設現在是台北時間週三 10:00（位於上班時段，`c = 40%/小時`），有兩個 `ok` 的 profile：

| 項目 | A | B |
| --- | --- | --- |
| 7d 已用 | 60% | 80% |
| 距 7d 重置 | 48 小時 | 20 小時 |
| 5h 已用 | 50% | 10% |
| 距 5h 重置 | 2 小時 | 2 小時 |

兩者的 5h 重置都在 12:00 前，共 8 個完整 slot，每個 slot 耗用 `40 × 0.25 = 10`，所以 `E = 80`。

| 計算 | A | B |
| --- | --- | --- |
| `w` | 100 - 60 = 40 | 100 - 80 = 20 |
| `T` | 48 | 20 |
| `U = (w - 2) / T` | 38 / 48 ≈ 0.7917 | 18 / 20 = 0.9 |
| `r5` | 100 - 50 = 50 | 100 - 10 = 90 |
| `F = min(1, r5 / E)` | min(1, 50 / 80) = 0.625 | min(1, 90 / 80) = 1 |
| `S = U × F` | ≈ 0.4948 | 0.9 |

兩者都通過剔除條件（`r5 > 2` 且 `w > 2`），也都不在收尾區間（`w` 皆大於 5），故在整個候選池取最高分，結果選 **B**。A 的 `U` 接近 B，但 5h 剩餘不足以撐到重置，`F` 打了折扣而落後。

## 調整指南

| 常數 | 目前值 | 調整的效果 |
| --- | --- | --- |
| 剔除門檻（`r5`、`w`） | 2% | 調高會更早放棄接近用盡的帳號；調低則更晚放棄，增加撞到上限的風險。`U` 公式中的 `w - 2` 為同一個安全邊際，須一併考慮是否同步調整 |
| 收尾區間上限 | `w` 在 2% 到 5% | 調高會讓更多「配額快用完」的帳號優先被消耗；設成 2 等於停用收尾偏好 |
| 收尾的 `F` 門檻 | 0.5 | 調高要求 5h 視窗更寬裕才執行收尾；調低則更積極收尾，但 5h 較可能中途耗盡 |
| `T` 下限 | 0.25 小時 | 調高會壓低「即將重置」帳號的 `U`；調低則重置前最後時刻 `U` 會急遽放大 |
| 上班時段耗用率 | 40%/小時 | 調高使 `E` 變大、`F` 更常打折，更保守 |
| 非上班時段耗用率 | 25%/小時 | 同上，作用於夜間與週末 |
| 上班時段 | 台北時間（UTC+8）週一至週五 09:00 至 19:00 | 改時區需同步改程式中的 `8*3600` 位移；改時段需改 `9*3600` 與 `19*3600` |
| slot 大小 | 15 分鐘（900 秒） | 調小可更精確但計算量增加；程式中 `900` 與 `0.25` 小時須一致調整 |
| 最終回退 | `onramplab` | 當 `active_profile` 也為空時使用的 profile 名稱 |

修改規則後，函式本體、本文件與 `tests/test-cli-aliases.sh` 必須一併更新，並實際執行測試確認通過。函式上方的註解區塊也屬於需同步的副本。

## 檢視實際決策

- 執行 `clauth status --json` 可看到選擇器的原始輸入，包含各 profile 的 `auth_status`、用量視窗與 `active_profile`。
- `clauto` 每次啟動都會在 stderr 印出 `==> [clauth] 選定 profile: <名稱>`，可據此確認實際選了誰。
- 要重現特定時間點的決策，可設定 `CLAUTH_PICK_NOW` 後直接呼叫 `_clauth_smart_pick`。
