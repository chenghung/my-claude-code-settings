# Shared Criteria

本檔是所有 prompt 定義檔類型共用的判準，撰寫時當規格遵守，審查時當檢查表逐項核對。

## Mandatory Wording Classification

本節檢驗檔案中的硬性規則是否必要：過多硬性規則會限制模型的情境判斷，並在跨檔案之間製造規則衝突，因此每一條硬性措辭都要能通過對應類別的檢驗才保留。

判定程序分兩步。

第一步，機械掃描取得候選清單：

```bash
rg -n '必須|一定要|絕對|禁止|不得|永遠|任何情況|一律' <target-file>
```

掃描結果只是候選清單，不是 findings。任何一條都必須走完第二步的分類與檢驗，才能判定為問題。

第二步，逐條分成三類，各走不同檢驗路徑：

| 類別 | 範例 | 檢驗方式 | 判定 |
| --- | --- | --- | --- |
| 一、安全或權限硬邊界 | 不得讀取憑證檔、只能修改指定目錄 | 是否有 permission 設定、hook 或 sandbox 真正執行 | 只有自然語言而無執行機制者判為假的保證，列 must-fix；此類措辭應更硬、邊界應更明確，不得放鬆 |
| 二、順序敏感的副作用檢查點 | 建立 PR 前必須先完成 push | 違反是否真會造成不可逆後果 | 是則保留硬性措辭 |
| 三、行為指引或風格偏好 | 必須使用繁體中文、一律使用條列 | 反例測試：刪掉這條後模型最可能怎麼做錯 | 說不出具體失敗場景者，建議改寫為原則或刪除 |

第一類的驗證著力點：本倉庫的權限與 hook 設定位於 `~/.claude/settings.json`（實際指向 `platforms/claude/settings.json`）與專案層 `.claude/settings.json`、以及本機專屬、未納入版本控制的 `.claude/settings.local.json`（若存在）。審查者應對照這些檔案的 `permissions.deny` 與 `hooks` 區塊確認宣稱的邊界是否真有執行機制，而不是僅憑 prompt 的文字敘述判斷。

## Acceptance Ambiguity

主觀詞在 prompt 中無處不在，全檔掃描會產生大量假陽性，因此本節不掃全檔主觀詞，只鎖定兩種會讓模型誤判自己已完成任務的位置：

| 位置 | 檢驗問句 | 可接受 | 不可接受 |
| --- | --- | --- | --- |
| 完成宣告點 | 模型要拿什麼證據才能說自己做到了 | 可觀察證據：指令輸出、檔案存在、欄位齊全 | 自我評估式說法：確認無誤、適當處理、審查通過 |
| 分支判斷點 | 這個條件能不能用是或否回答 | 檔案路徑位於某目錄下 | 訊號模糊或互相矛盾時 |

明確排除於檢查範圍之外：背景說明、設計理念、以及其他不導向具體行為的敘述性文字，這些位置出現主觀詞不列為 finding。

## Safety Boundary

本節檢查各類 prompt 定義檔是否清楚宣告了可以做什麼與不可以做什麼。檢查項目四條：

- **職責邊界成對出現且互斥**：subagent 須同時具備 `In Scope` 與 `Out of Scope` 兩節，且兩者內容不重疊；skill 須在 description 中同時寫出觸發與不觸發情境；command 須寫明適用範圍。
- **宣稱的硬邊界有實際執行機制支撐**：判定方式沿用本檔 `Mandatory Wording Classification` 的第一類，對照權限與 hook 設定驗證。
- **subagent 的 `tools` 欄位最小化**：授權的工具超出職責所需即為 finding，例如唯讀審查角色被授權 `Write` 或 `Edit`。
- **破壞性或不可逆操作標示邊界**：刪除檔案、推送遠端、寫入外部服務等操作，須明確寫出什麼情況下可做、什麼情況下不可做。

## Forbidden Patterns

以下行為對所有 prompt 定義檔類型一律禁止：撰寫時不得寫入，審查時發現一律列為 finding。本節不規定發現後的處置，分級與採納依 `SKILL.md` 的 `Findings Grading and Adoption` 節判定。

- **Table of Contents**：不得在檔案頂端放置人工維護的目錄（Table of Contents）。這類檔案會整份載入 LLM context；ToC 對 LLM 沒有導航價值，純屬 token 浪費，且在章節重新命名時會增加同步維護成本
- **Hardcoded credentials**：不得寫入 API 金鑰、access token、含 token 的 webhook URL 或任何敏感資訊；一律改用環境變數或外部 secrets 管理機制

## Content Necessity

prompt 定義檔只應寫入模型無法從自身訓練資料或工具自身介面推斷出來的內容；重述模型已內建的知識會浪費 token、稀釋真正重要的專屬指令，且會在模型知識演進後與檔案內容產生過時矛盾。

應寫入的內容限定為以下五類：

- 此 repo 或此 domain 特有、無法從通用知識推斷的慣例，例如 commit message 格式、特定知識庫的 typed frontmatter 欄位規則
- 具副作用且順序敏感、非直覺的流程檢查點，例如建立 PR 前必須先完成 push
- 外部工具的已知 quirk 或 bug
- 安全與權限邊界，例如禁止讀取某個 credential 設定檔
- 與 main agent 的成功與失敗輸出契約，包含應回傳哪些欄位、遇到哪些情況應停下並詢問使用者

禁止寫入的內容包含但不限於：

- 標準語法或語言特性教學，例如 Markdown / CommonMark / GFM 語法、程式語言語法、通用框架的標準用法
- 透過 help 指令或工具自身 schema 即可取得的 CLI flag 或參數逐項清單（型錄式窮舉）
- 模型已能自行推理的常識操作順序，例如先讀檔再編輯、先搜尋再判斷
- 已有工具會強制執行的規則之逐條複述，例如定義檔內已會呼叫 linter 時就不需再逐條教 lint 規則

**CLI 範例的界線**：上述「CLI flag 或參數逐項清單」的禁令，指型錄式窮舉某工具所有子指令與選項，這仍一律禁止。唯一例外：當完成某操作的 CLI 指令存在多種合理但不等價、不可互換的推導結果，且選錯會破壞輸出契約、造成不可逆或順序敏感的副作用、或導致跨次執行結果不可重現時，允許放入最小的 canonical 呼叫範例並要求照此執行——只釘住真正需要固定的一兩條具體呼叫，不列整個指令表面，並簡述為何必須是這個形式而不逐項解釋每個 flag 的語意。若所有合理推導都等價，或選錯只會明顯失敗且能無害自我修正，則不適用此例外。

**模型能力與執行具體度的兩軸**：內容類型限制對所有 model 等級一律適用，不因模型較小而放寬——較小模型同樣內建標準語法等通用知識，且更容易被冗長 prompt 帶偏，這是軸一（內容類型，天花板固定）。已落在應寫入五類內的合法內容，特別是副作用順序檢查點與 CLI canonical 範例，允許依模型能力調節說明的詳盡程度：能力較強的模型給意圖與約束、信任其自行推導；追求快速的小模型則寫得更逐步、更釘死，這是軸二（執行具體度，地板浮動）。軸二只能在已合法的內容範圍內提高具體度，不得以模型較小為理由跨入軸一的禁區。

本節與下方 `Wording Criteria` 章節分工不同：本節判斷內容該不該存在於檔案中（內容層），`Wording Criteria` 的 token 閘門判斷內容通過本節後該用什麼措辭強度表達（措辭層）——內容須先通過本節，才輪到 `Wording Criteria` 決定如何措辭。

## Wording Criteria

措辭軸七條規則。適用前先過 token 閘門：措辭軸的 findings 必須先通過內容必要性檢驗——只有在該內容是模型推不出、且確實需要存在時，才要求為它增加措辭；模型推得出或本來就不必要的內容，不要因為措辭規則而要求把它補上。

- **R1 針對具名失敗模式下指令，而非抽象美德。** 自我檢測：這條規則對應到哪一個會犯的具體錯誤，說得出來嗎。適用邊界：行為類規則適用，純事實或格式宣告不強求。
- **R2 每節以一句可壓縮的論點開場。** 自我檢測：把這節壓成一句話，模型還能照做嗎。適用邊界：有多條細則的 section 適用。
- **R3 措辭強度依三分類決定，不一律偏向禁令。** 先依 `Mandatory Wording Classification` 判定類別，再決定措辭形式：
  - 第一類安全邊界用明確禁令，且必須有執行機制支撐。
  - 第二類副作用檢查點用硬性措辭，並寫出違反的具體後果。
  - 第三類行為指引改用原則或條件判斷，不用禁令；預先假設所有情境相同的清單式硬規則，會在特殊任務中造成錯誤限制。

  自我檢測：這條屬於哪一類，措辭強度與該類相符嗎。
- **R4 每條有明確對錯的規則配一個可證偽的自我檢測句**，問句須能用是或否回答。自我檢測：模型讀完知道怎麼自我驗收嗎。適用邊界：純偏好性或情境依賴性強的規則可省。
- **R5 用錯誤與正確對比錨定容易被誤解的規則。** 預設不加，僅在誤解會造成實質錯誤行為時才加。自我檢測：這條容易被誤解嗎。
- **R6 有例外情境的規則必須寫出什麼條件下不套用。** 自我檢測：這條什麼時候不該套用，有寫出來嗎。適用邊界：安全性與正確性的硬約束不設豁免。
- **R7 對於模型推不出根因的專屬約束，補充機制性說明**，使模型能在未列舉的情境下自行推斷。自我檢測：遇到沒列舉的情境，靠這條的為什麼模型能自己判斷嗎。適用邊界：此處的為什麼必須是專屬且推不出的根因，通用常識不補。
